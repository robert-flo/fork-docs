# ADR-008 — Cadencia Desatendida 04:00 AM y Escudo de Conflictos

* **Estado:** Aceptada
* **Fecha / Hito:** 2026-09-30 (Plan de automatización y CI/CD cruzado)

---

## Contexto

El proyecto upstream [`omacom/omarchy`](https://github.com/omacom/omarchy) lanza actualizaciones constantes. Anteriormente, el mantenedor debía monitorear GitHub manualmente, hacer `git fetch upstream`, rebasear `personal` en su terminal local y disparar la Action de empaquetado.

El objetivo planteado por el usuario fue: *"quiero que suceda automáticamente a las 4:00 AM todos los días, así me despertaré y si hago un `omarchy update` en la mañana estaré en la versión más reciente"*.

---

## Decisión

1. **Sincronización Desatendida Cruzada:**
   * Se programa un cron diario a las 04:00 AM en `sync-check.yml`.
   * Al detectar un tag nuevo, se dispara `release-personal.yml` con la deploy key SSH `SSH_OMARCHY_SOURCE_KEY`.
   * El runner ejecuta Fast-Forward de `quattro` y `git rebase quattro` sobre la rama `personal`.
2. **Escudo ante Conflictos (*Conflict Containment Shield*):**
   * Si ocurre un conflicto de código durante el rebase, el pipeline ejecuta `git rebase --abort`, aborta la compilación para no publicar software roto, y abre un GitHub Issue de alerta con la lista de archivos y comandos de resolución local.
3. **Gestión Automática de GitHub Issues:**
   * El pipeline abre un issue de seguimiento al detectar el tag y lo **auto-cierra** tras verificar que la nueva versión responda `HTTP 200` en GitHub Pages.

---

## Consecuencias

* **Operación Zero-Touch:** Las máquinas amanecen sincronizadas sin que el mantenedor deba intervenir.
* **Seguridad Absoluta:** Ante cualquier divergencia profunda de upstream, el sistema se detiene en seco antes de tocar los paquetes en producción.
