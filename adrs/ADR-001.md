# ADR-001 — Hosting del Repo Pacman Personal: GitHub Pages + GitHub Actions

* **Estado:** Aceptada
* **Fecha / Hito:** 2026-09-01 (Etapa 3, WORKLOG 4ª parte)

---

## Contexto

El sistema personal necesita un repositorio `pacman` propio que las máquinas cliente puedan consumir de forma natural durante la ejecución de `omarchy update`.

Buscábamos un entorno de compilación e integración continua (CI) para no depender de la máquina local del mantenedor, y una entrega estática segura mediante HTTPS sin incurrir en costes de infraestructura dedicada (sin servidores VPS, sin buckets S3 ni almacenamiento rclone propio).

---

## Decisión

1. **Alojamiento Estático:** El repositorio se sirve desde `robert-flo/omarchy-personal-repo` en la rama `gh-pages` bajo el canal único `stable`.
2. **Fábrica de Compilación:** Los paquetes se compilan mediante GitHub Actions en `robert-flo/omarchy-pkgs` replicando el pipeline oficial de Omarchy (`build → sign → promote → update → clean`).
3. **Mecanismo de Despliegue:** La entrega final se realiza mediante `git commit` y `git push` directo a la rama `gh-pages` en lugar de sincronización rclone.
4. **Seguridad Cross-Repo:** El runner de GitHub Actions se autentica contra el repositorio CDN mediante una Deploy Key SSH dedicada (`SSH_DEPLOY_KEY`) con permisos de escritura.

---

## Consecuencias

* **Disponibilidad:** Servido por la red CDN global de GitHub con certificado SSL/TLS administrado automáticamente.
* **Archivos Planos:** GitHub Pages no soporta enlaces simbólicos; por tanto, los índices `omarchy.db` y `omarchy.files` se resuelven como copias binarias reales firmadas criptográficamente.
* **URL Canónica:** `https://robert-flo.github.io/omarchy-personal-repo/stable/x86_64/`.

---

## Alternativas Descartadas

* **Hosting en servidor casero / NAS:** Descartado por falta de alta disponibilidad y dependencia de IP dinámica.
* **Registro OCI (GHCR / Docker Registry):** Descartado porque `pacman` nativo requiere un servidor HTTP estándar con base de datos de paquetes `.tar.zst`.
