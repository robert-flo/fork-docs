# ADR-004 — Regla del `pkgrel` Alto (99+) y Autoderivación

* **Estado:** Aceptada
* **Fecha / Hito:** 2026-09-01 (WORKLOG 7ª parte y revisión L8)

---

## Contexto

Pacman evalúa la precedencia de paquetes utilizando el algoritmo `vercmp`:
1. Compara primero la versión base (`pkgver`).
2. A igual `pkgver`, compara el número de release (`pkgrel`).

Upstream publica cada nueva versión con `pkgrel=1` (por ejemplo: `4.0.4-1`). Si publicáramos nuestras personalizaciones con `pkgrel=1`, cualquier máquina podría descargar indistintamente el paquete oficial o el personal dependiendo del orden de caché, perdiendo las personalizaciones. Además, si publicamos cambios sobre el mismo `pkgver` sin incrementar el release, pacman consideraría que no hay actualización disponible.

---

## Decisión

1. **Base Alta `99`:** Para cualquier versión nueva (`pkgver`), el paquete personal se publica con `pkgrel = 99` (ej. `4.0.4-99`).
2. **Incremento Monótono:** Cada republicación de personalizaciones sobre el mismo `pkgver` incrementa en +1 el release (`4.0.4-100`, `4.0.4-101`, etc.).
3. **Autoderivación en CI/CD:** El workflow `release-personal.yml` inspecciona automáticamente el estado actual en el CDN y deriva el `pkgrel` correcto sin intervención humana.

---

## Consecuencias

* **Prevalencia Garantizada:** `vercmp 4.0.4-99 4.0.4-1` devuelve siempre `1`. Pacman jamás instalará el paquete oficial por error.
* **Cero Errores Manuales:** Se elimina el riesgo de olvidar incrementar el release durante un despliegue manual.
